- **Baseline to Preserve:** the **shopping list's "store references, derive on render" design** (`src/db/state.ts` stores `{ id, servings }[]` + a separate extras/checked set; `src/utils/shopping.ts::aggregateShoppingList` reconstructs the grouped, amount-summed list at render time from the read-only recipes). Because nothing materialized is persisted, a recipe edit in `recipes.yaml` is reflected on the next render with zero migration, and there is structurally no second recipe write-path to keep in sync. The checked-item lifecycle is closed correctly too: `pruneCheckedItems` drops keys whose line has left the list, so a removed-then-re-added ingredient can never resurface pre-checked. New per-device features should copy this reference-not-snapshot shape.
